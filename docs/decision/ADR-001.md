# ADR-001: Use Department-Scoped Role-Based Access Control

## Status

Accepted

## Context

The Internal Operations Service Hub has different types of users:

- Employees
- Department Staff
- Managers
- Administrators

These users require different levels of access.

Employees should only be able to view their own requests.

Department Staff should only be able to view and process requests that belong to their department.

Managers should be able to monitor requests belonging to their department.

Administrators should manage users, departments, roles, permissions, and system configuration.

The system therefore needs a clear way to control access to requests and system features.

## Decision

The Internal Operations Service Hub will use department-scoped Role-Based Access Control.

Each user will have one or more roles that determine what actions they can perform.

Department Staff and Managers will also be associated with a department.

The backend will check both the user's role and department before allowing access to protected requests or actions.

## Reason

This approach matches the structure of the Internal Operations Service Hub.

It provides clear separation between departments and prevents users from accessing information they are not authorized to see.

It also makes permissions easier to understand and manage.

## Consequences

Employees will only access their own requests.

Department Staff will only process requests belonging to their department.

Managers will only monitor requests belonging to their department.

Administrators will manage system configuration and permissions.

Authorization checks must be implemented in the backend and should not depend only on hiding options in the user interface.

If access requirements change in the future, the roles and permissions may need to be extended.
